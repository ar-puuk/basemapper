## Verdict

The **bones are genuinely impressive**. The two hardest problems are solved well:
headless single-pass vector rendering through `maplibre-rs` + `wgpu` (`renderer.rs`),
and a deferred tmap-v4 aux-layer integration that correctly forces the 3857 display CRS
(`tmap_integration.R`). The R/Python API surface is symmetric, well-documented, and the
error taxonomy is thoughtfully typed end-to-end (`error.rs::kind()` → `core_err_to_py`).

**But it is not yet distributable.** "Does it actually work" currently has the answer:
*only on your machine.* That is the gap between a competent prototype and a legendary
package. Issues below are ordered by how much they block distribution.

---

## 🔴 P0 — Blocking (doesn't work for anyone but you)

### 1. Build is non-reproducible — depends on a private fork via a local path patch

`Cargo.toml:20-21` and `r-basemapper/Cargo.toml` both patch `maplibre` to a sibling checkout:

```toml
[patch."https://github.com/ar-puuk/maplibre-rs"]
maplibre = { path = "../maplibre-rs/maplibre" }
```

- The fork `../maplibre-rs` exists **on your disk only**. A fresh clone — CI, a CRAN/PyPI
  builder, or any user — cannot compile `core`, the Python wheel, or the R package.
- `r-basemapper/src/basemapper.dll` (21 MB, built locally) is git-ignored, so `install_github()`
  will not ship it. README's claim that "end users need only R itself" (`README.md:239`) is false.
- The SHA pin in `core/Cargo.toml:14` is 39 hex chars (truncated — missing 1 char); git will
  reject this rev on a clean fetch. The commit log says rev `1a930af` but Cargo.toml says
  `3bb17231fc7895248bb3cd8a3882d472d74c12c` — these disagree.

**Every other correctness claim is unverifiable until this is resolved.**

**Fix (pick one):**
1. Upstream the `pub` visibility changes into mainline `maplibre-rs` and depend on it directly
   (your own comment at `Cargo.toml:17-19` says "No source changes were needed" — if true, you
   may not need the fork at all).
2. Vendor the fork as a `git submodule` or `git subtree` inside this repo at a pinned commit,
   point the patch at the in-repo path.
3. Remove the `path` patch entirely; use a git-rev patch so resolution works everywhere.

### 2. No CI that builds or tests anything

`.github/workflows/` has only `core-sync-gate.yml` (a `diff -r` of vendored core) and `docs.yml`.
There is **no** `cargo test`, `cargo clippy`, `R CMD check`, or `pytest` job on any platform.

**Fix:** Add a 3-OS matrix (ubuntu / macos / windows) that, once P0#1 is resolved:
- `cargo build`, `cargo test`, `cargo clippy -D warnings`, `cargo fmt --check`
- Build the Python wheel + run `pytest`
- `R CMD check --as-cran`

## 🟠 P1 — Industry-standard gaps (needed before public release)

### 3. Test suite avoids the actual render path

- `r-basemapper/tests/testthat/test-render.R` (18 lines): only asserts function signature and
  that `geom_basemap()` returns a layer — never renders a pixel.
- `py-basemapper/tests/test_render.py`: exercises error handling well but every
  `render_basemap_raw` call deliberately fails *before* the network/GPU (version 7 style, invalid
  bbox). Nothing tests a successful raster or vector render.
- Real integration coverage lives in `core/tests/render_integration.rs` (good, uses `httptest`),
  but gated behind the un-buildable fork.

**Fix:** Add snapshot/golden-image tests in both R and Python — render a fixed bbox against a
mock tile server (or a tiny embedded PNG), compare output within pixel tolerance. This is the
highest-signal test for the compositor and crop/resize math.

### 4. R package will not pass `R CMD check --as-cran`

- `DESCRIPTION:10` `License: MIT` → must be `MIT + file LICENSE` with a 2-line LICENSE file
  (`YEAR:` / `COPYRIGHT HOLDER:`). No LICENSE file exists.
- `DESCRIPTION:27` `Config/roxygen2/version: 8.0.0` → roxygen2 has no 8.x; should be
  `RoxygenNote: 7.3.x`. Man pages may not have been regenerated by real roxygen2.
- Missing `URL:` and `BugReports:` fields.
- `terra` is in `Imports` but is only used in the optional tmap path — move to `Suggests`
  (already guarded by `requireNamespace()` in `tmap_integration.R:67`).
- README says users need `stars` for tmap (`README.md:25`) but code uses `terra`. Doc drift.

### 5. Python packaging metadata incomplete for PyPI

`pyproject.toml [project]` lacks `readme`, `authors`, `urls`, `classifiers`. No `py.typed`
marker means type hints are invisible to downstream `mypy`. License format should be SPDX
`license = "MIT"` + `license-files`.

### 6. Raster compositor can produce 1-px seams — contradicts the "pixel-accurate" claim

`renderer.rs:33-34`: each tile's pixel size is rounded independently
(`tile_px_w = (tile_size_m * scale_x).round()`), then placement is also independently rounded
(`px_x = (...).round()`). Adjacent tiles can overlap or leave a 1-px gap.

**Fix:** derive each tile's right/bottom edge from the *next* tile's rounded origin (snap to a
shared integer grid), not by rounding size and origin separately.

## What's genuinely good — keep / don't touch

- `CopySurfaceNode` + `InMemoryCaptureSystem` headless capture plugin — sophisticated, correct
- Anti-meridian split-and-stitch (`lib.rs::render_antimeridian_split`, `bbox.rs::tile_count`)
  coherent end-to-end including zoom and tile-count math
- Typed error mapping across the FFI boundary (`error.rs::kind` → Python exception hierarchy
  that subclasses both `BasemapError` and `ValueError`)
- Vendored-core drift gate (`core-sync-gate.yml`) — cheap, effective guard for Option-A vendoring
- Symmetric, well-docstringed R/Python provider catalog
- Deferred `GeomBasemap` draw: tile fetch at draw time so `coord_sf()` has already set extents

---

## Recommended execution order

1. **Resolve maplibre-rs fork dependency** — upstream it or vendor in-repo. Removes the local
   `[patch]`. *Nothing else is verifiable until this lands.*
2. **Stand up CI** — build + clippy + fmt + `cargo test` + `pytest` + `R CMD check` on 3 OSes.
3. **Add real render tests** — golden-image snapshot in R and Python using a mock tile server.
4. **CRAN/PyPI metadata cleanup** — license files, `RoxygenNote`, field additions, `py.typed`.
5. **Fix raster seam math** and P2 correctness nits (auth URL, `.Call` symbol).
6. Defaults, `NEWS.md`, docs-in-CI, friendliness polish.

Items 1–3 are the difference between "a clever prototype on one laptop" and "a package people
depend on." The hard engineering is behind you — what remains is reproducibility, verification,
and distribution hygiene.

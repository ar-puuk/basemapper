# basemapper audit — round 1 (report only, no code changed)

**Date:** 2026-11-23 · **Branch:** `dev` @ `6a69b01` · **Scope:** performance, efficiency,
user API, security, bugs. No new features.

**Yardsticks:** Rust API Guidelines + clippy (core), tidyverse style & design guide +
rOpenSci packaging guide (R), PEP 8 / PEP 257 / Scientific Python packaging guide (Python),
OWASP guidance for clients that fetch untrusted input (security).

Confidence: **[C]** confirmed by reading the code path end to end; **[L]** likely, needs a
profile or test to size it.

## 1. Bugs

| # | Sev | Finding | Where |
|---|-----|---------|-------|
| B1 | **High** | **`max_tiles` is not enforced for vector tiles.** `render_style` lowers a *raster* zoom until `tile_count <= max_tiles` and checks that, but the vector path ignores that zoom and fetches `covering_tiles(bbox, tz)` at the scale zoom. A 16384 px wide view at z14 fetches ~1000 tiles with `max_tiles = 256`. Secondary sources (raster/DEM/extra vector sources in `fetch_vector_inputs`) and the whole SVG path never check `max_tiles` at all. That breaks the providers' fair-use limits the setting exists to protect. [C] | `core/src/lib.rs:425-443`, `:1035-1165`, `:1199` |
| B2 | Med | **R casts wrap silently.** `tile_zoom as u8`: `256L` becomes 0 and `300L` becomes 44 (the comment says the core rejects bad values, but they never reach it). `max_tiles as u32` / `tile_timeout_ms as u32` with a negative R integer become ~4.29e9, which turns the tile limit off and sets a ~50-day timeout. Python is safe because PyO3 rejects negatives. [C] | `r-basemapper/src/rust/src/lib.rs:66,75-77` |
| B3 | Med | **`tile_concurrency = 0` hangs forever** in the Rust API (`Semaphore::new(0)`). The R and Python bindings clamp it with `.max(1)`, but `Basemap::tile_concurrency(0)` and `RenderRequest` don't, and `validate()` doesn't check it. [C] | `core/src/tile_fetcher.rs:301`, `core/src/bbox.rs:74` |
| B4 | Med | **A failed attribution lookup is cached as `""` for the whole R session.** One network blip means no credit line on any later plot, which is a licence-compliance problem (OSM, CARTO, etc.). [C] | `r-basemapper/R/layer_utils.R:98-100` |
| B5 | Low | Wrong error variants: errors for `pixel_ratio` and `tile_zoom` use `InvalidBbox`, so users see "invalid bbox: pixel_ratio 0 must be > 0". [C] | `core/src/bbox.rs:113,124` |
| B6 | Low | `Basemap::zoom()` (Rust builder) doesn't validate, but `set_view` does. Latitude is never range-checked anywhere. [C] | `core/src/basemap.rs:370` |
| B7 | Low | PMTiles fetch ignores `fail_on_tile_error`, drops task panics (`JoinError`) without a word, and has no concurrency limit. [C] | `core/src/lib.rs:834-866` |
| B8 | Low | Sprite index: `x + w` with huge JSON integers wraps in release builds, passes the bounds check, then `get_pixel` panics. A malformed remote sprite crashes the render instead of being skipped. [C] | `core/src/vector/symbol.rs:925-927` |
| B9 | Low | Font cache ignores `BASEMAPPER_CACHE_DIR=off` and `tools::R_user_dir()`. It writes under `~/.cache` even when the user turned caching off. [C] | `core/src/vector/fonts.rs:418-466` |
| B10 | Low | `geom_basemap()` doesn't expose `tile_concurrency` / `fail_on_tile_error`, though `basemap()` does. [C] | `r-basemapper/R/geom_basemap.R:153` |

## 2. Security

| # | Sev | Finding | Fix direction |
|---|-----|---------|---------------|
| S1 | **Med** | **Secrets leak into error messages and logs.** `TileFetchFailed{url}` and `StyleFetchFailed{url}` print full URLs, including `?key=`, `?apikey=` and `access_token=` (MapTiler, Thunderforest, Stadia, and the `access_token` the core appends itself). These reach R/Python error text, `log::warn!`, CI logs and bug reports. `TileIsWebPage` already redacts; the others don't. | Redact credential-like query params (`key`, `apikey`, `api_key`, `access_token`, `token`) in one `Display` helper used by every error and log line. |
| S2 | **Med** | **`auth_token` goes to every host a style mentions.** It is sent as `Authorization: Bearer` to the style, any TileJSON host, every raster tile host and the type probe, and appended as `access_token=` to *every* vector tile URL (a Mapbox convention) whatever the host. A style that mixes a keyed provider with a third-party overlay hands the key to the third party. (reqwest strips the header on cross-host redirects, so only these explicit sends are affected.) | Scope the token to the origin of the style/TileJSON it was given for. Only append `access_token` for Mapbox hosts, or make it opt-in. |
| S3 | Med | **No size limits on downloads or decompression.** Tiles, styles, TileJSON, GeoJSON, glyphs, sprites and fonts use unbounded `bytes()` / `text()` / `json()`. reqwest auto-decompresses gzip/brotli, and `mvt::decode` gunzips with `read_to_end`. A hostile or broken server can exhaust memory (decompression bomb). This matters most when basemapper runs inside a server (Shiny, FastAPI) that renders user-supplied styles. | Cap bodies per kind (e.g. tiles 16 MiB, styles 32 MiB, GeoJSON 256 MiB) by streaming with a counter; use `.take(limit)` on the gzip reader. |
| S4 | Low | **A remote style can read local files and reach internal addresses.** `pmtiles://file:///…` in a downloaded style is read from local disk (`ArchiveBackend`); sources may point at `127.0.0.1` / `169.254.169.254` (SSRF). This is harmless on a desktop and relevant only for server deployments. | Only allow local paths when the *top-level* input is local; optionally add `BASEMAPPER_ALLOW_PRIVATE_HOSTS`. |
| S5 | Low | SVG `<style>` block: font family names come from the style's `text-font` and are only stripped of `'`, not escaped for `<` / `&`. Exploiting it needs a font that resolves under that name, so the practical risk is low, but it is still an injection pattern. | Escape (or whitelist characters in) the family name in `font_face_css`. |
| S6 | Low | SVG export contacts Google Fonts by default, so the user's IP goes to Google. This is undocumented as a privacy behaviour (GDPR-sensitive users). | Document it; consider opt-in. |
| S7 | Low | **Supply chain / CI:** no `cargo audit` / `cargo deny`, no workflow `permissions:` block (default token scope), actions pinned by tag, not by SHA. R `Makevars` runs `cargo build` without `--locked`, so `install_github()` can resolve dependency versions other than `Cargo.lock`'s. | Add `cargo deny check` (advisories + licences), `permissions: contents: read`, and `--locked` in Makevars / Makevars.win. |

## 3. Performance and efficiency

These are ordered by expected payoff for real use. Redraw-heavy paths (ggplot resize,
`ggsave`, knitr, tmap) re-run the whole pipeline each time.

| # | Kind | Finding | Expected gain |
|---|------|---------|---------------|
| P1 | Network | **A new `reqwest::Client` is built for every render** (`http_client()` in `render_part`, `render_async`, `list_layers`, `attribution`, `tile_style`, SVG). Each one rebuilds the rustls root store and throws away the connection pool, so no keep-alive and no TLS session reuse between renders. The per-request `.timeout()` already exists, so one shared client is a drop-in change. | Large on redraws: removes a TLS handshake per host per render [C] |
| P2 | Network | **Only tiles are cached.** The style JSON, TileJSON, sprite (json + png, often 4 requests with the @2x fallback), every glyph range, and the PMTiles header + directories are fetched again on every render. A ggplot resize in RStudio can mean 10–30 round trips before any tile. | Large: a byte-bounded in-memory LRU for these resources, keyed by URL [C] |
| P3 | Latency | **Independent fetches run one after another.** Sources are awaited one by one in a `for` loop. The sprite is fetched after the glyphs, though it doesn't depend on them. Stack parts (`UGRC.Lite` = 3 styles) and the two anti-meridian halves render one at a time. | Medium: `join!` / `JoinSet` here [C] |
| P4 | CPU | **Every vector tile is decoded twice**: once in `fetch_glyphs` (to find the glyph ranges) and again in `place_tiles`. Tile bytes are also cloned twice (`(*d).clone()` into `placed`, plus `all_vector`). | Medium [C] |
| P5 | CPU | **Filters and expressions are interpreted from `serde_json::Value`** with string-matched ops, for every feature × every layer (`features()` → `eval_filter`). MapLibre compiles them once per layer. Compiling them to an enum tree per render keeps the output pixel-identical. | Likely the largest CPU item [L: profile first] |
| P6 | CPU | **Tile decode and per-tile tessellation run on one thread.** They are independent per tile and can run in parallel without touching the drawing order, so the goldens stay byte-exact. | Large on multi-core for big views [L] |
| P7 | Build | **No `[profile.release]` tuning** (`lto = "thin"`, `codegen-units = 1`). Typically gives 10–20% on CPU-bound Rust like this renderer. It applies to the wheel and the R build for free. | 10–20% CPU [L] |
| P8 | CPU | The style JSON is parsed or serialised about 5 times per render (validate, `filter_layers`, `features::select`, `render_style`, `fetch_vector_inputs`). | Small–medium on big styles [C] |
| P9 | Memory | The tile LRU is bounded by count (512), not by bytes, so 512 large tiles can mean hundreds of MB. Every hit copies the `Vec`; use `bytes::Bytes` / `Arc<[u8]>`. The disk cache does blocking `std::fs` I/O on tokio workers and opens each hit twice (read, then `set_modified`). | Small–medium [C] |
| P10 | R | **`plot()`, `geom_basemap` and tmap convert the image to a double array** (`/ 255`, 8 bytes per channel, ~384 MB for a 4000×3000 image) and then call `as.raster`. Passing a `nativeRaster` (packed 32-bit, as the png/ragg packages do) is roughly 8× less memory and much faster to draw. | Large for print-resolution plots [C] |
| P11 | Python | `np.frombuffer(bytes).copy()` makes one extra full-image copy per render. Returning a writable buffer (a `bytearray`, or building the numpy array in Rust) avoids it. | Small [C] |

**Before any of this:** add a small `criterion` benchmark (2–3 golden fixtures: a city
view, a dense z14, a raster stack) so each change is measured, not assumed.

## 4. User API

What the API already gets right: R, Python and Rust use the same verbs; Python uses
keyword-only arguments; the error taxonomy (`kind()`) is clear; catalogue names
are forgiving.

| # | Finding | Recommendation (precedent) |
|---|---------|----------------------------|
| A1 | **Four network-tuning arguments are repeated in every entry point** (`tile_timeout_ms`, `max_tiles`, `tile_concurrency`, `fail_on_tile_error`), in `basemap()`, `render_basemap_raw()`, `geom_basemap()` (two of the four), `tm_basemap()`, plus the Python mirrors. They make `basemap()` 16 arguments long for settings most users never touch. | Bundle them: R `fetch = fetch_options(timeout = 10, max_tiles = 256, concurrency = 16, on_error = c("skip", "fail"))`, Python a frozen `FetchOptions` dataclass, Rust a `FetchOptions` struct. Precedent: `readr::locale()`, `ggplot2::arrow()`, httr2 `req_options()`. Optionally add session defaults via `options(basemapper.fetch = …)`. This takes `basemap()` from 16 arguments to 12, with full control kept. |
| A2 | Units in argument names (`tile_timeout_ms`). | Seconds, as in tidyverse, httr2, requests and urllib3: `timeout = 10`. |
| A3 | **Two names for one credential:** `auth_token` (render) vs `api_key` (`basemap_provider`). | One name, `api_key`, falling back to the provider's env var (the catalogue already knows it: `ApiKey.env`). Keep `auth_token` as a deprecated alias for one release. |
| A4 | R: optional arguments can be given by position, so `basemap("X", c(-111, 40), 12)` puts the centre into `width` and fails with a confusing error. | Put `...` after the required arguments and check it with `rlang::check_dots_empty()` (tidyverse design guide, "dots after required"). Python already does this with `*`. |
| A5 | `labels` takes `TRUE` / `FALSE` / `"only"` (a mixed type). | Document the strings `"all"`, `"none"`, `"only"` as the main form (they are already accepted) and keep the logicals as shorthand (tidyverse: "use strings for enumerations"). |
| A6 | R errors are plain `stop()`, so R users can't catch by kind, though Python has `ValidationError` / `StyleError` / `NetworkError`. | `cli::cli_abort(class = c("basemapper_network_error", "basemapper_error"))`, using the core's `kind()` (r-lib cli / rlang conventions). |
| A7 | **Heavy hard dependencies.** R imports sf, terra, ggplot2 and jsonlite. sf and terra need GDAL/GEOS/PROJ on Linux and on macOS source installs, which contradicts the "no system GIS libraries" promise. Python requires matplotlib, xarray and pyproj. | R: move terra, ggplot2 and tmap-adjacent code to Suggests, guarded by `rlang::check_installed()`. Do lon/lat ↔ 3857 in the core (it already has the maths), so `sf` is needed only for non-4326/3857 CRSs. Python: extras such as `basemapper[matplotlib]` and `basemapper[xarray]` (Scientific Python packaging guide). |
| A8 | `render_basemap_raw()` duplicates `basemap()` + `render_array()`, and the `_raw` suffix reads as internal. | Keep it, but document it as the low-level one-shot function, or soft-deprecate it in favour of `render_array(basemap(bounds = …))`. |
| A9 | Rust: `RenderRequest` has all-pub fields and `BasemapError` is exhaustive, so any field or variant added is a breaking change. | `#[non_exhaustive]` on both, before any crates.io release (Rust API Guidelines C-STRUCT-PRIVATE, future-proofing). |
| A10 | Python `Basemap` exposes mutable public attributes (`m.labels = "bogus"`) with no validation after `__init__`. | Use properties, or a frozen dataclass plus `replace()`. |

## 5. Tooling gaps (best-practice baseline)

- CI runs tests and `R CMD check`, but has **no `cargo clippy -D warnings`, no `cargo fmt --check`, no `cargo deny`, no `ruff` / `mypy`, and no `lintr`**.
- R `Makevars` builds into `$(CURDIR)/../../target`, which is outside the package directory once installed from a tarball. That writes to the parent of the unpack directory (CRAN policy forbids this; harmless for GitHub installs today, but fragile).
